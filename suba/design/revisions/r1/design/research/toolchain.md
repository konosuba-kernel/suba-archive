# 工具链、自举边界与内核实现约束调查

日期：2026-10-13。节点 B，候选 r1。本文是源码和既有产物调查及设计建议，不是 suba 已实现或自举通过的声明。需求依据为 `../../REQUIREMENTS.md`；编译器依据为 `biomiya@2c7061c` 的 `core-s/next/q/`，不以旧 `core-s/runtime/` 代表当前 Q 运行库。

## 1. 结论

当前语言足以表达第一版系统的主体。首先要补的是**编译器运行环境边界、目标入口/布局、汇编到 S-next 的固定桥接、有限机器指令及系统内构建发布工具**，不是泛型、函数指针、分配器内建或优化框架。

现有 Linux-user 自编译确实成立；它不能证明编译器已经能在 suba 运行。只替换 `runtime/linux.vt` 不够。当前生成的 ELF 自带 Linux 退出代码，诊断和文件发布还在其他模块直接调用 Linux syscall。必要特权指令缺失，普通 S-next 函数和静态对象甚至没有可让 S0 按名字调用/取址的导出符号。

建议保留同一个编译器、同一种 RV64 指令生成、直接生成最终 ELF。用**编译器运行环境**和**编译产物 profile**两个正交概念，避免把“编译器在 Linux 运行”和“只能编译 Linux 程序”混为一谈。第一阶段不做 `.o`、任意链接脚本、动态链接、包管理或通用汇编宏系统。

## 3. 已有语言能力及其责任界线

| 能力 | 已有事实 | 系统中的用法/限制 |
|---|---|---|
| 内存和对象 | 数组、结构、具体枚举、`static mut`、`zero`、显式初始化；无 allocator/GC | 静态表负责元数据；物理页和用户区域由系统自己分配和回收。无语言 allocator 不等于不能实现页分配器 |
| 指针/切片 | `core::ptr`、`addr_of`、`ptr_add`、`slice_from_raw_parts`；需 unsafe | 可描述物理页、页表、缓冲；有效期、对齐、权限仍由系统证明 |
| 下标和算术 | 下标界限与普通算术有运行期检查；panic 不展开 defer | 内核输入必须先显式校验再访问，不能把应用恶意输入变成内核 panic；退出回收不能依赖应用 defer |
| 内存复制 | 没有用户可调用的通用 copy/fill 内建；生成器有聚合复制例程 | 定义少数经过审查的复制/清零函数。编译器内部复制例程不是 usercopy 安全机制 |
| MMIO/原子 | 无 volatile 语义，也无通用 atomic 内建 | 用有限 S0 外部函数明确 8/32/64 位访问和 fence；普通指针访问不得当设备读写。DMA 提交/完成的内存序仍需机器层合同 |
| 整数 | bool/u8/u32/usize；无 u16、有符号、浮点 | 磁盘/virtio 小端 u16 用显式字节编解码；有符号相对输入在边界解码并限制范围。不要把硬件布局直接等同本语言结构布局 |
| 调用 | 直接函数调用和受限 RV64 标量/指针 extern C ABI | 少量 `match kind` 静态分派处理驱动/对象种类即可；不为事件循环引入函数指针、闭包、虚表 |
| 资源清理 | 保存实参的直接调用 defer，正常控制流退出执行，panic 不执行 | 内核资源账本和进程终止路径是完整回收的基础；defer 只辅助局部已获得资源的回滚 |
| 可变静态 | 显式 unsafe，无借用检查、线程安全证明 | 单核不等于无并发：中断、抢占、等待仍会改变状态。按所有者、临界区和状态机处理 |
| 静态分析 | 已有 Blocking 路径分析 | 可以辅助约束不可等待路径；它不是调度器、任意终止性证明，也不能证明设备一定完成 |

参考手册事实依据：`docs/reference/s-next-0.1.md` §6–11。当前缺少的语言特性暂不列为阻塞。新的系统 API 应先用现有标量、切片和具体结果枚举表达。

**安全 usercopy 建议：**内核把用户传入的地址当整数范围处理；先检查溢出、用户地址界限、每一页的映射/权限，再经受控物理映射逐页复制。内核不能随意解引用应用地址，更不能在异步 I/O 中保留用户裸指针。固定首版可采用内核拥有的有界 bounce buffer；设备只接触被内核持有的页，完成或取消后由唯一所有者释放。若允许进程在请求期间改变映射，需固定页或在每次拷贝时重新检查；仅“开始时检查一次”不够。整体节点 C 当前选定请求仅保留 `UserRange { pid, generation, address, length }` 与请求令牌，不保留裸指针或 pin 用户页；单线程等待期间不能自己改变映射，完成时重新 walk/校验、校验进程代次与令牌后才 copyout。kill 撤销令牌后禁止 copyout。DMA bounce 则必须等待设备完成，或队列 reset 已确认设备不再访问后才能回收；撤销用户访问权和释放设备 buffer 是两个不同的时点。

## 4. 最小工具链改造

### 4.1 编译器运行环境与输出目标分离

以相同模块接口提供 Linux 和 suba 两种运行环境源文件，由构建清单显式选择其中之一；不引入动态插件或条件编译语言。这个接口只覆盖参数、输入文件、有界读写、诊断、退出、产物完成/删除。`model` 的终止诊断走这一出口，`input` 不再自行调用 syscall。Linux 的 chmod 留在 Linux 实现中。

运行在 Linux 的过渡编译器应能产生 suba 编译器/应用/内核；运行在 suba 的后继编译器也应能选择相同目标。目标 ISA 仍只有 RV64，禁止以“多目标”名义建立通用后端框架。

### 4.2 四个固定产物 profile（含可信启动种子）

| profile 建议名 | 入口、终止和布局 |
|---|---|
| `linux-user` | 保持当前初始栈/参数、0x10000 起三段 ELF、Linux 退出/panic，保留回归 |
| `suba-user` | loader 提供已验证参数块和用户栈；固定用户 VA、三段权限、BSS 清零、guard；返回/panic 走 suba exit/trap；不伪装 Linux fd/errno ABI |
| `suba-kernel` | 固定物理/虚拟布局与启动 ABI；最小机器入口建立栈及进入 S-next 前置条件；trap 入口保存/恢复完整现场，kernel 返回或 panic 停机 |
| `suba-boot` | 平台节点首选固定 stage0：位于 kernel 之外，从固定原始磁盘 extent 加载 kernel；它是公开源码与构建规则的可信启动种子，正式闭环不要求在运行系统内更新该种子 |

数值由平台节点 A 与整体合同 C 冻结，不在本文另建不一致内存图。平台首选 OpenSBI 外部固件 + 固定 stage0 + 磁盘 kernel；显式 `suba-boot` 比在 kernel profile 隐藏 boot 子模式清楚。四份有限配置不是任意地址链接器。stage0 不得收纳 kernel trap/设备服务来规避系统内重建要求。

`image` 只接收一份已验证的固定布局记录。修补计算应使用 region base，不能残留 `65536 + offset`；入口所属段、数据绝对重定位和所有有符号 PC 距离均验证边界。第一版坚持非 PIE、无动态重定位、无加载后链接。

### 4.3 汇编/S-next 桥接是阻塞项

当前函数符号匿名，用户函数也不能写成 `extern abi(C)` 定义。建议由 kernel profile 的固定桥绑定表建立保留符号：机器入口调用的 S-next 启动函数、陷入分派函数、kernel panic 终点；机器层需要的栈/现场地址也由显式受限绑定或生成入口参数传递。每项必须验证存在、类别、签名、唯一性和 target 适用性。

建议绑定名对应 `kernel_entry(bootinfo:usize)`、`trap_dispatch(frame:usize)` 和 panic hook；这些都是现有普通函数语法，不发明 AST 特性。当前 `selected_entry` 明确拒绝参数，所以要新增 kernel 专属签名校验/入口生成；当前普通标量参数来自 a0–a7（`rv64.vt:556`、`:1267`），可以为这些有限桥生成确定代码。x27 在现有发射器中仅由 Linux start 写入并供参数 S0 读取；suba profile 可选保存参数块指针于 x27，但必须规定机器包装保留它，trap 保存/恢复它，不能继续假设其内容是 Linux 初始栈。

桥接不新增可取函数地址的语言表达式。外部机器 ABI 仅传 usize/指针等现有标量；固定胶水负责从标量寄存器到 S-next 调用约定的转换。不能靠“目前看起来都是 a0/a1”把内部 ABI 宣称为通用 C ABI。trap frame 可是内核普通结构，但汇编偏移应由合同统一定义并有生成/双向探针，不能两份手写常量长期各自漂移。

### 4.4 S0 只扩系统需要的机器操作

建议新增经过独立编码验证的 CSR 读/写/置位/清位、`sret`（仅在方案确需 M-mode 时加 `mret`）、`wfi`、`sfence.vma`、`fence`、`fence.i`。CSR 号/立即数字段必须专门验证，不能复用当前有符号 12 位立即数解析后掩码。需要 trap vector 对齐时提供受限且有上限的 text 对齐；不引入任意 sections/directives。

现有 lbu/lwu/ld 和 sb/sw/sd 足以组成首版 MMIO 宽度包装。第一版单核不因 P5 曾使用 AMO 就强制添加完整原子指令集；只有平台路径实际需要时扩充对应指令及 acquire/release 编码测试。地址常量、启动栈和 boot metadata 必须通过固定符号/布局合同生成；避免靠外部 `.incbin`、GNU 宏或链接脚本暗中回到宿主构建。

完成扩展后，suba 必要机器源码统一采用可由原生 Q 消化的 S0。现有 GNU `monitor.S` 继续作为外部测试设施，不成为正式内核无法自行重建的依赖。

## 5. 容量、模块和内存

本轮实读 E3：SHA-256 `7e1de550da39c31e203c83d0bce7e13dd5deb64923f3c5e4428aad8fbd7d7d20`；文件 **999,504 B**，RW `p_memsz` **55,135,764 B**，三段地址跨度 **56,131,092 B**。前者约 55.1 MB/52.6 MiB，不能把“55MB”误写为 55MiB。静态 reservation 不是实测峰值 RSS，也不是整个系统预算。release 的最大单函数 frame 25,808 B 不是整个调用链栈峰值；当前自举试验给 guest 栈 1 MiB。

55 MB 中已经包含编译器静态源码、ELF输出、符号等 arena，系统内存预算不能把这些内部数组又逐项算一遍；进程实际栈、页表、内核、桌面、文件缓存、其他进程及内核 I/O staging 仍须另计。先以固定较宽裕 QEMU RAM 建立闭环，再测量收紧；不承诺 128 MiB 足够完整桌面自举。

| 约束 | 当前值/证据 | 规划影响 |
|---|---|---|
| 编译器自身输入 | 16 VT + 1 S0，332,326 B VT | 为运行环境拆分/桥接留余量；不用另造编译服务常驻进程 |
| 单产物源文件 | 32 VT + 8 S0 | 内核、桌面、编辑器、编译器、构建工具各有显式清单；共享库文件计入各自清单 |
| 输入容量 | 清单16KiB、VT总4MiB、S0总1MiB | 分块组织源目录不等于容量取消；在 CI 输出每份清单消耗与余量 |
| 名字/类型/声明 | 各8192；当前名字4067 | 名字往往先于源码字节成为约束，新增目标/运行库后重新实测 |
| 符号/修补 | 32768/65536；当前12660/27672 | 不应将“内核代码小”替代后端容量检查 |
| 数据/最终映像 | 已初始化数据池8MiB；总映像跨度64MiB | 字体等资产不要做巨大 S-next 常量；装载为独立文件。系统RAM可超过64MiB，物理页池无需塞进ELF BSS |
| 每函数 | AST/slots32768，IR/labels65536；256参数 | 分解高复杂函数，勿通过无边界扩大表隐藏结构问题 |

如果合理模块划分确实超过 32 个源文件，建议第一档明确放宽到 64 个 VT（S0 仍按实需），而不是强迫巨型文件。需统一修改 `input.sources`、`input.headers`、初始化循环及两个添加入口，尤其 `types.vt:19` 的 `module_state:[33]u32` 也必须同步；共享常量若跨模块静态数组长度的当前语法不能表达，就保留少量具名合同值并加一致性检查。源码字节4MiB、名字8192等容量不随文件数机械翻倍。先报告具体清单和余量，重跑63/64/65及模块导入边界负例、量化增加的静态内存并更新手册。禁止只改 parser 中的一个数字，或并置两个实际上无法共同链接的“内核”清单。没有行数天花板不等于没有产物容量。

## 6. 可执行的自举验收顺序与信任链

以下是后续实现的验收门槛，不是本轮已经执行的测试。每一步保存源码清单、工具/配置身份、产物哈希、目标 profile、日志与失败记录。

1. **T0 运行环境/target 解耦。**冻结现有 Linux E3 种子；用它构建改造后的 Linux 编译器 L1，再由 L1/L2 取得 Linux 固定点。重跑现有语言/输入/机器/限制/接口/复制/参考/Blocking 回归，另验 suba profile 拒绝未绑定入口、重复/错签名桥、越界布局。此时仍未证明 suba 自举。
2. **T1 机器层最小证明。**独立机器编码参考对照新增 S0 指令的合法/非法操作数；运行 QEMU 验证 trap 完整寄存器保存、CSR、页表刷新、I-cache发布、定时器恢复；直接编译得到正式 profile ELF，无宿主链接器修补产物。验证普通应用的 panic 与内核 panic 去往不同终点。
3. **T2 系统内编译普通应用。**L 构建 suba 编译器 C0 并放入初始盘；在 suba 内编辑 manifest/源、启动 C0、显示诊断、完整保存并装载应用。应用创建、执行、退出真实经过最终系统机制；错误源码、磁盘满、取消构建、输出句柄关闭失败不会发布成功产物。
4. **T3 编译器原生固定点。**C0→C1→C2→C3 均在 suba 内完成，同一清单要求 C1=C2=C3 全文件字节一致；再次修改编译器可观察诊断/行为，原生构建并观察变化后恢复。仅相同哈希不足以排除拿旧二进制冒充编译。Linux 与 suba 编译器生成同目标/同源码时也应作产物比较，差异必须解释。
5. **T4 内核及必要机器层原生重建。**系统内编辑内核 S-next 和 S0，各作一次可观察变化；原生构建 ELF、校验并写入待启动产物、完成块设备刷新、再选择下一次启动。重启后观察新的内核与汇编行为，核对运行版本身份。宿主只能启动/重启 QEMU 和观察，不参与重链接、重打包、复制新kernel到宿主路径。
6. **T5 完整开发闭环回归。**编译期间桌面仍响应；反复失败/终止编译器后页面、句柄、等待、窗口回到基线；正常关机重启后源码/产物完整，接着在新kernel内再次完成编译器/应用构建。将字体、构建工具、内核、机器层的成本与外部资产分别记账。

**可信种子：**QEMU/初始固件或明确 boot0、已有 Linux E3、初始源码与磁盘生成器在第一次引导中可信；后续链从真实 C0 的执行开始。若保留不可变 boot0，它只负责启动选择/最小加载，必须公开其源码、字节身份和未纳入原生重建的边界；内核陷入、必要驱动机器操作和普通系统构建绝不能藏进 boot0。平台若选择可更新第二级 loader，该级源码和装配/发布也进入 T4。

**系统内构建组织：**一份显式有限顺序的系统构建清单即可，按 compiler/app/kernel 等目标调用同一个编译器进程，再调用小型本机校验/发布程序。无需移植 make 或 shell。编译器一次编译一个产物，结束后由内核整体回收其静态地址空间；编译器当前不承诺重入、并发服务或取消后复用内部全局状态。

**发布与重启：**编译器写临时/新文件，成功写完并关闭后由构建工具请求校验/发布；kernel 启动槽位应在完整输出及正常 flush 后才切换。具体槽/文件格式由文件系统和启动合同冻结。这里要求正常流程可回退到已有有效内核，不增加突然掉电事务恢复承诺。系统编译产物的数字签名和安全启动不在需求中。

## 7. 进入实现前必须冻结的合同

- 平台启动件、kernel 物理/虚拟地址、应用入口参数布局、panic/exit、四种 profile 的精确值。
- trap/启动桥的保留名字、标量签名、保存寄存器集合、栈对齐和不可重入区间；S0 与 S-next 共享的现场偏移验证方式。
- 内核映射用户内存的策略、copyin/copyout 的页权限及请求持有期；等待/取消后的数据与页所有权。
- 编译器 I/O 适配错误表示、写入完成、文件关闭/flush、发布和磁盘满时的失败路径。
- 所有产物清单容量、编译器实际运行内存/栈、字体资产如何供给，以及完整 T0–T5 的依赖顺序。

上述条目是系统设计的输入，不向用户重新索取已经授权由工程选择的细节。架构节点 C 应选定这些合同，未验证的机器行为则作为有界探针门槛列入实施计划。
