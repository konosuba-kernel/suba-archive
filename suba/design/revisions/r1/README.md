# suba

konOSuba 的新内核与系统环境：主要使用 S-next 和少量汇编，运行于固定的 QEMU RISC-V 64 虚拟机器。

目标是整体设计并构建一个可理解的系统：隔离的多进程、持久文件存储、可重叠窗口桌面、支持 UTF-8 和中文字形的编辑环境，以及能够在系统内重建编译器、内核和必要汇编部分的工具链。

## 当前状态

2026-10-14：需求与全局架构设计已整理，尚未实现内核。已确认范围及验收场景见 [REQUIREMENTS.md](REQUIREMENTS.md)。设计及验收状态见 [设计交付记录](design/DELIVERY.md)。

- [整体架构](design/ARCHITECTURE.md)：系统边界、部署、状态归属、自举链和成本。
- [核心合同](design/CONTRACTS.md)：地址空间、入口、等待、回收、存储与窗口生命周期。
- [实施计划](design/IMPLEMENTATION.md)：依赖 DAG、分阶段探针及整体验收。

首版选择小型模块化宏内核、隔离进程、独立可信桌面，以及普通编辑器/编译器；固定 QEMU RV64 单核、512 MiB RAM、ramfb 软件图形。已有平台调查只验证部分设备协议和入口/复位行为，完整系统内构建与磁盘重启闭环仍待实现。

`SOS/` 已弃用，其需求、宿主化路线和实现选择不作为 suba 的约束。当前编译器基线来自相邻 `biomiya/` 仓库的提交 `2c7061c`，参见 [S-next 使用参考](../biomiya/core-s/docs/reference/s-next-0.1.md)与[编译器交付记录](../biomiya/core-s/next/q/release.json)。编译器已有 Linux-user 自举证据，suba 内的自举仍是待实现目标。

架构清晰是硬要求，没有预设的代码行数上限。内核、驱动、文件系统、桌面、编辑器、用户库和系统内构建工具均记录实际成本；编译器、测试、外部基础设施和字体数据分别列账。
