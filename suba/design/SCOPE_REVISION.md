# 首版范围修订：原生构建与内核部署分开

2026-10-14，版本 0.2。用户明确同意保留系统内应用编译、编译器固定点及内核/S0原生构建，将系统内安装、切换和回退内核移出首版。本文落实该决定，不改变“自举、简单、现代”的优先级。

## 必须完成的闭环

1. 在 suba 桌面编辑、正常保存源码，原生编译并运行应用。
2. 在 suba 中完成编译器 C0→C1→C2→C3 全文件固定点，并以源码行为扰动排除旧产物替代。
3. 在 suba 中分别修改内核 VT 和必要 S0，编译得到完整可启动 ELF；正常持久保存输出及构建输入身份。
4. 宿主读取或导出已保存的文件，只按字节搬运并验证完整身份，经固定 RAM 启动链装载新内核，观察对应变化，再在新内核中编译应用。

同输入的 Linux/suba 构建全文件对照属于独立测试；为此运行宿主编译器是允许的 oracle，但该输出不得代替 guest 产物部署。部署路径上禁止宿主重新编译、汇编、链接、重打包或修补 ELF。记录 guest 输出、搬运副本和实际装载文件的完整字节身份。加载配置可以解析 ELF 范围并设置引导参数，不能改写 ELF。固定的是可信 RAM 引导基础、命令结构和加载规则，本次 kernel 输入当然可以改变。

准确的交付表述是“原生构建完成，部署仍依赖宿主”。Linux-user 固定点、UART 演示、宿主生成的新内核均不能代替这些门槛。固定 RAM 引导基础与 OpenSBI 暂不要求 guest 重建；内核必要 S0 不在此例外内。

## 延期和保持

| 内容 | 首版决定 |
|---|---|
| 磁盘 stage0、A/B安装/选槽/回退、启动选择记录更新 | 延期 K1；不再阻塞 K4/K9/K10 |
| 磁盘 stage0 的原生构建检查 | 随 K1 延期 |
| K4 最小 virtio/block 传输、IRQ、FLUSH、持久 FS | 必需；K4 存储负责人唯一拥有传输/队列生命周期，延期 K1 将来复用底层，不复制实现 |
| 已冻结启动槽常量、布局、发布系统调用号 | 保留而不复用；首版发布调用返回 Unsupported，不授予槽写能力；FS 仍从 65 MiB 开始 |
| 正常文件 sync、正常关机、重启后读取 | 必需；不因部署简化而降低持久性语义 |
| 普通应用隔离、抢占、完整资源回收 | 必需 |
| 重叠窗口、UTF-8与中文字形、源码编辑和构建诊断 | 必需 |
| 突然断电事务恢复、复杂排版、中文输入法 | 继续不要求 |

K9 改为原生 kernel/S0 ELF 构建与宿主仅搬运部署验收。K4 不再等待 K1，先基于 K2/K3 的内存、请求、退出体系完成运行期存储。共享 ABI 数值和原磁盘格式不因范围缩小而重做。普通构建产物的文件发布与延期内核槽发布是两个不同操作：前者仍必须通过现有文件生命周期完成。

## 本轮实现边界

沿 K0 已验收的固定 RAM 引导→BootInfo→S-mode 内核路径推进 K2a：物理页分配、清零、身份验证、回收和真实 QEMU 接入。K2a 不声称完成页表、用户 trap、抢占、进程隔离或 K3 系统调用。完整 K2 验收仍是进入 K3 的门槛。本轮依赖和独立验收见 [K2 内存起点](../docs/workflows/k2-memory/DELIVERY.md)。

本次同步 REQUIREMENTS、README、ARCHITECTURE、CONTRACTS、IMPLEMENTATION；CODE_STYLE 0.1 仅纠正迁移后的参考路径和 K0 已实现状态，规范强度不变。当前编译器在 `biomiya/compiler/`，测试/工具在 `biomiya/tests/`、`biomiya/tools/`；历史调查原文中的旧路径和规模保留为当时事实，参见 [目录迁移](../../biomiya/docs/layout-migration.md)。

旧设计 C-r3、规约验收和 K0 I-r2 验收仍证明各自冻结内容；不能以它们的旧文件哈希宣称本次范围修订已经验收。旧报告、候选、历史研究与 ABI 常量不改写。本次 R 候选记录受影响文件的新身份及其旧身份，交由 root 独立验收；K0 机器行为证据可复用，其历史文档输入不再代表当前规范文本。
