# suba 0.1 系统使用参考（交付候选）

本文随 K8–K10 实施更新，当前不是阶段完成声明。验收状态以
[推进记录](../workflows/through-k10/DELIVERY.md)与独立报告为准。

## 系统边界

suba 是固定 QEMU RISC-V 64 平台上的 S-next 系统：OpenSBI 提供固件服务，少量 S0
实现启动、陷入和机器访问；应用运行在独立 Sv39 地址空间中。普通应用越界、非法指令、
崩溃或死循环可被终止，其资源经有限步骤回收。内核和驱动属于可信部分；可信错误可停机。

设备组合固定为 virt、1 hart、512MiB RAM、256MiB 原始磁盘、modern virtio-blk、
virtio keyboard/tablet、1024×768 ramfb。它没有 Linux 系统调用兼容层，也不承诺任意
RISC-V 硬件、动态设备发现、网络、多核或热插拔。ABI 数值来源为 `abi/`，不要在应用中
复制另一套猜测的系统调用号。

## 编辑、编译和运行

现有桌面提供两个可重叠编辑器，分别打开 `/work/hello.vt` 和 `/work/notes.txt`。
应用从自己的窗口接收输入；可信桌面负责摆放、焦点、拖动与强制结束。

| 操作 | 键位 | 当前语义 |
|---|---|---|
| 保存 | Ctrl+S | 写临时文件、完成后替换并同步；失败不冒充已保存 |
| 构建 | Ctrl+B | 保存后启动构建工作进程，默认读取 `/work/program.build` |
| 运行 | Ctrl+R | 启动当前已发布的输出，不隐式重新编译 |
| 诊断定位 | Ctrl+J | 仅输入内容仍匹配诊断身份时定位；编辑后的旧诊断不会错误跳转 |
| 取消构建 | Esc | 终止本次构建子树，未发布的临时内容由内核回收 |
| 打开文件 | Ctrl+O | 输入 `/work` 下已有文件的相对路径 |
| 重新打开编辑器 | Ctrl+Alt+E | 最多两个编辑器 |
| 强制结束应用 | Ctrl+Alt+Esc | 由桌面能力终止焦点应用 |

UTF-8 按 Unicode scalar 编辑，支持 BMP 中文字形；没有中文输入法、grapheme 编辑或复杂排版。
四字节字符保留其原始 UTF-8 字节，缺字以占位显示；组合字符按各 scalar 分别处理。
字体源和许可保存在 `assets/unifont`，初始盘中也保留署名。

单文档上限 4MiB、诊断日志 1MiB、进程内剪贴板 64KiB。边界是显式容量，不是按需扩张承诺。
文件系统普通文件上限 16MiB，与 ELF 的 64MiB 虚拟地址跨度是两个独立限制。

## 构建与部署的区别

`/sys/compiler.elf` 是同一 S-next 编译器核心配 suba host 模块。构建工作进程创建 Job，
复制输入、冻结快照、收集编译输出，只在输出完整、封存并通过 ELF 检查后发布。
保存、构建和运行是不同动作；编译期间继续修改编辑器内容不会改变已经冻结的输入。

K8 的目标是系统内 C0→C1→C2→C3 固定点，并修改编译器源码验证行为确实改变。
K9 的目标是系统内分别修改 VT 和 S0、生成完整内核 ELF，然后由宿主仅搬运文件来部署。
这两项的实际完成状态必须查看独立报告，不能由本参考的目标描述推断。

`boot/ram.vt` 是固定 RAM 启动基础，启动时读取描述及 ELF 范围；`tools/ram_launch.py`
不编译或链接。其 `--sha256` 必须来自待部署 guest 完整产物的身份记录。该工具拒绝身份
不符、坏 ELF、越界或超大文件；不会修补一个损坏产物使其可启动。
磁盘 stage0、内核槽安装/选择/回退属于延期 K1，不在首版闭环中。

## 保存与故障

只有成功完成同步才能把保存视为持久化。突然断电时的事务恢复不属于当前承诺；合法
Transient/Detached 在正常重挂载时先经过完整所有权校验，再有界回收，不能借回收忽略坏盘。
实际设备错误或超时进入存储故障停机，不能当作普通应用可恢复错误。

若发生停机，保留完整 serial.log、run.json、源码/ELF身份和原始磁盘副本。
不要先重建或重新格式化唯一的失败盘。历史未解释事件与修复证据见工程记录。
正常关机入口和完整成本账将在 K10 正式实现/验收后补齐到本文。
