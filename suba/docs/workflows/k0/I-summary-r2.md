# K0 组合交付候选 I-r2

范围、生产实现与完整回归继承 [I-r1 组合说明](I-summary.md)；r1 已被 [独立验收](acceptance-r1.md)拒绝，唯一阻断是正常交接后发生紧急异常仍被观察器接受。r1 候选、判定和真实反例保留，变更文件的旧字节保存在 `revisions/i-r1/`。

r2 只修改 suba 的观察工具、负控及对应文档/证据；编译器、内核 VT/S0、ABI 与平台生产文件均未变，不重新执行无关的完整自举。

每条路径现在只允许boot进入标记后恰好一个合法终态：正常交接、指定reason=1的拒绝，或完整scause=2/sepc/stval异常行。混合终态、重复终态、boot panic、颠倒顺序、截断异常或错误cause均拒绝。正常路径另显式拒绝紧急异常前缀。观察持续500ms，并在结束后再次检查全部输出。

独立验收的真实反例已纳入启动检查：在忽略目录的源码副本中，于handoff accepted之后插入 `unimp`，重新用同一E3编译并启动QEMU；必须实际按顺序看到成功和非法指令异常，且观察结论为失败，才能把该负控记为通过。因此本版启动检查为3条正向预期路径加1条真实错误路径负控。观察器另检查4个真实进程行为和20个终态序列。

修正过程保留一次失败：初版一读到 `!` 就终止QEMU，正确判失败但截断了UART异常字段，使负控无法确认实际cause。现改为收集完整观察窗口，最终统一拒绝错误终态；失败记录和原因见 [r2证据索引](I-results-r2.json)。

当前源码、结果与成本分别由 `I-candidate-r2.json`、[证据索引](I-results-r2.json)、[成本记录](I-cost-r3.json)冻结。独立判定仍以 `acceptance-r2*` 和 [DAG](DELIVERY.md) 为准。本轮没有增加K1磁盘闭环或K2进程机制，有限观察也不证明无限期稳定性。

冻结r2时另检测到外部工作区对 `biomiya/tools/check_next.py` 删除一处行尾空格。保留该改动，旧字节归档；Python AST完全一致，原执行记录仍标记原工具哈希。[差异记录](I-concurrent-tool-cleanup.json)交独立验收确认影响，不把新工具哈希冒充已运行身份。
