# K0 组合交付候选 I-r1

作者 `/root`；独立判定见本目录 `acceptance-*` 与 [DAG](DELIVERY.md)。本文是实现和机械证据报告，不代替独立验收。

## 当前结果

编译器位于 `biomiya/compiler/`，根目录运行所有维护命令。四种固定 profile、有限 panic/trap 桥和 S0 系统指令已接入同一个 Q；编译器宿主操作收束到 `runtime::host`，目标布局由 `bootstrap::target` 管理。核心语言语义、32 源/8 汇编容量与冻结种子没有改变。

`suba/kernel/` 已有最小 S-mode 入口：检查本阶段允许的 BootInfo，建立早期异常路径，通过 UART 报告交接后停机。普通 panic 输出原因；可信非法指令输出 scause/sepc/stval。fw_cfg 探针通过正式 S0 的 `sh` 验证 16 位 selector、QEMU 签名和目录计数；包装接口拒绝未对齐地址与超宽值。

boot 是测试 fixture：QEMU 预加载独立 kernel ELF，fixture 复制 DTB、生成 BootInfo 并跳入 kernel。没有磁盘加载、页表、调度、进程回收、文件系统或图形桌面；没有在 suba 内运行编译器。BootInfo 当前只检查可信启动所需的窄边界，完整格式/保留区域/FDT 校验归 K1。真实 trap 保存与用户恢复归 K2。系统调用编号是分配合同，不表示服务已经实现。

## 证据与失败记录

[证据索引](I-results-r1.json)保存 23 份完整记录的副本及原位置/哈希。现有十组 Q 回归共 435 场景：语言126、机器105、输入24、复制8、保存故障12、诊断18、Blocking48、接口76、容量15、参考3。K0 专项另为 profile26、S0 167、host3。冻结种子91、P3 126+11、表示试点8、系统切片和验证器保护88+5分别记账，不重复加总成单一覆盖率。

本轮新目录下的 suba 三条启动路径均通过：正常交接、坏 magic 拒绝、可信非法指令。观察器的成功标记后延迟 panic 和立即退出反例都正确失败；稳定进程正例通过。工具观察标记后继续500ms，再主动停止 QEMU；有限观察不能证明无限期停机或稳定性。

保留的失败包括：旧 P3 源快照不能认证新 Q；初期 S0 使用不支持的 `andi`；C-r1 把 kernel end 误写为 length；观察器初期见标记立即停止；机器旧用例把新增支持的 `csrrw` 当成不支持。后者改用仍不支持的 `csrr` 伪指令，CSR 的接受/拒绝与编码由新增专项验证；没有删掉拒绝检查。对应修正记录见 [用例迁移](I-machine-case-migration.json)、[观察器预审](I-preflight-review.md)和 C-r1/r2 判定。目录迁移自己的失败与重跑见 `biomiya/docs/layout-verification.json`。

迁移前的八份测试清单补充 host/target 依赖发生在旧 P4 之后；它们不属于生产自举输入。新目录 P3/P4 和机器105项已在完整迁移后的清单上验证，当前交付不再依靠旧 P3 的宽泛快照覆盖声明。

## 成本与下一步

[当前成本](I-cost-r2.json)按物理行统计：Q 生产 VT 11,307 行，运行支持另375行 VT和19行S0；kernel 152行VT、111行S0，共263行；共享ABI另199行。测试和Python工具分别列账，不算进内核也不隐去。

编译器 ELF 1,036,432 字节，RW 55,135,836 字节，映像跨度56,168,028字节，最大函数帧25,808字节。kernel ELF 20,481字节，映像跨度147,472字节，其中RW 131,088字节包含128KiB栈。boot fixture ELF 20,481字节，映像跨度213,520字节。当前 compiler/kernel/boot 分别18/3/5个VT源和1份S0，不需要增容。

K0 通过后可进入 K1：用固定 stage0 从磁盘槽加载内核，在同一个 QEMU 进程内写入新槽、FLUSH、SRST，并实际运行新版本。不能用本轮 RAM 交接替代该验收。
