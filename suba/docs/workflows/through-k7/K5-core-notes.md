# K5 共享核心接入与证据边界

2026-10-16，root 实施；独立验收另行记录。基线是已接受的 K4 提交 `10de32f`。
新模块、桌面和驱动的过程见 [K5工程记录](K5-engineering-notes.md)。
原始报告身份见 [核心证据索引](K5-core-evidence.json)。

共享入口仅将 boot image 0 授予 Desktop 能力。普通运行相同程序不获授权；
不相干的 File、Stream、Job 操作显式拒绝 Desktop 类型。窗口创建和复制沿用
同一 request token，进程终止沿用已有句柄/子树/地址空间清理，退出发布还等待
FS及窗口资源归零。表面立即撤权、分片回收的合同已同步写入 CONTRACTS。

调度每批最多32片，每片先服务真实IRQ，再推进FS和dispatch；达到1ms后不再
开始下一片。这个阈值不保证最后一片恰好在1ms内结束。有可运行后台工作时用户
量子1ms，否则10ms；不存在工作时不消耗空window/child轮次。FS用已有detached
账本跳过无对象时的回收扫描。usercopy保持先验证完整范围、逐页权限检查，再在
有效普通RAM上使用对齐usize复制，不引入用户VA直接解引用或MMIO普通访问。

## 集成验证

- `k5-integrated-contracts-r3` 复用与桌面相同的最终观测内核：非法尺寸、跨页范围、
  对象权限、窗口配额和旧句柄拒绝通过；普通显示内存写被隔离，最终表面归零、页
  回到同次桌面基线。r1/r2是更早版本，不能替代r3身份。
- `k5-integrated-gtk-r4` 使用 `k5-integrated-desktop-r3` 的冻结kernel/user ELF，
  真实QEMU GTK/XTest完成重叠、焦点、键下/键上、拖动、协作关闭、无响应关闭及
  Ctrl+Alt+Esc强杀。全程18.68s，最终free=123997、surface=0。root检查了拖动
  截图；QMP仅用于截图观察。该测试不等于人工物理键盘验收。
- 原`k5-integrated-desktop-r3`报告仍为失败：末步采样点恰好被白色光标覆盖。
  相邻点和完整资源账本已经恢复；r4在发热键前移开光标，像素断言保持原样。
  未改ELF、未覆盖旧失败。父报告失败与后续独立GUI运行通过需要分别阅读。
- `tools/check_k5_storage.py` 复用K4原有断言。仅在测试源码副本将boot夹具设为
  普通应用；真实K5键鼠设备和共享IRQ路径保留。所有实际编译输入另行散列，
  `--kernel-from`仍逐文件核对。生产引导授权不受测试适配影响。

## K5-C01：完整内核触及旧宿主编译超时

类别：测试工具容量；状态：已明确分离构建与运行期时限。

`k5-storage-filesystem-r1`、`k5-storage-cancel-dma-r1`在宿主运行S-next编译器时
达到旧K2工具的240秒构建时限；没有ELF、没有启动guest，不能记成存储运行失败。
保留失败报告。当前清单已从K4的50VT增长到60VT，新增观测路径也参与编译。
共用命令入口增加显式timeout参数和超时输出记录，组合探针的宿主构建时限改为
600秒；guest的180秒存储运行、90秒像素检查及设备deadline均未放宽。

这暴露了编译规模和测试成本：后续编译器性能工作应测量真实完整清单，不从小
例子外推。构建时限只防止测试永久挂起，并非语言或内核性能通过标准。

## 尚未解决的性能目标

GTK最终实测首次重叠1.87s、提到前台2.65s、键下1.87s、键上3.45s、拖动2.91s。
相比最初每片间完整10ms量子的几十秒迟延已有改善，但仍有秒级重绘。此次功能
证据不证明100ms交互目标，也不证明两个编译任务后台运行时的延迟分位数；原计划
将这些测量目标与K10整体成本核验分开。不得把“30Hz上限”写成实测达到30fps。

K7仍需实际FS映像装载、作业冻结权限、编辑器和原生编译集成。当前桌面测试中的
应用来自RAM夹具，当前GUI没有编辑/构建界面；不能以本阶段通过代替K7/K8。

当前正式清单60个VT、3个S0。带明确K5观察点的组合内核ELF为1,450,032字节，
text=1,439,216字节，最大单函数frame=10,368字节；桌面ELF=122,881字节。
这些数值来自`k5-integrated-desktop-r3`实际编译输出，包含内核所有运行支持，
不冒充未经插桩的正式发布镜像或完整调用链栈/系统规模账。

组合存储回归结果：`k5-storage-filesystem-r2`两次启动持久文件操作通过；
`k5-storage-boundaries-r1`同内核两启动跨页、大小和权限边界通过；
`k5-storage-cancel-dma-r2`两启动各100轮真实DMA取消，全部资源账本恢复。
共享调度和输入IRQ接入没有用旧K4报告代替这些组合场景。该正控重新运行，
SEIE-off负控仍只有已接受K4版本证据，不声称已在K5重跑。
