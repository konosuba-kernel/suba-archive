# 实现问题与改进依据

这是语言与系统架构后续改进的证据索引，独立于阶段交付状态。失败不从记录中删除；修好后补结果及对应候选/提交。探索记录不等于生产缺陷，也不等于已通过阶段验收。

每项记录至少包含：稳定编号、类别、影响阶段、状态、症状、复现入口或证据身份、已确认原因与未确认部分、处理结果、可供后续评估的改进方向。没有验证的建议仅记为候选，不自动扩大本轮实现范围。

类别区分：编译器/语言实现缺陷、语言现行规则或容量限制、系统实现缺陷、架构或性能难点、设备/平台限制、测试夹具缺陷、工具与证据管理问题。不能把被语言明确禁止的写法，或正常拒绝旧证据的验证器，记成编译器BUG。
